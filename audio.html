The Audio Stack

Three buses, three runtime sinks, one music director. This page is the map of every seam a sound can enter the game through — and the style contract that keeps new clips sounding like they belong.

The rebuild menu item

Run Gleamwood ▸ Audio ▸ Create + Route Game Audio Mixer (AudioMixerBootstrap.Run() in Assets/_Game/Editor/AudioMixerBootstrap.cs). Unity has no public API for authoring mixer assets, so it drives the internal AudioMixerController via reflection. It is idempotent — safe to run any time:

  • Mixer exists with all 3 groups + all 3 exposed params → kept as-is. A partial asset from a failed earlier run → deleted and rebuilt.
  • Routing sweep: every prefab under Assets/ gets all its AudioSource components (including inactive children) pointed at the SFX group. Re-running just re-sweeps.
  • Console confirms with [AudioMixer] ready at {path}; routed N prefab AudioSource(s) to SFX.

When to run it: on a fresh setup with no mixer, after adding any prefab that carries an AudioSource (the sweep wires it for you), or after a broken half-created mixer.

Editor-window quirk: the bootstrap deliberately skips AddGroupToCurrentView (mixer views are window display filters and the call needs window state that doesn't exist headless). If a freshly created group doesn't show in an already-open Audio Mixer window, the view is stale — the group is real.

02The three runtime sinks

Nothing to place in scenes. All three lazily create their own DontDestroyOnLoad object on first use or boot.

GameAudio — combat SFX

Assets/_Game/Systems/Audio/GameAudio.cs. Static class; call GameAudio.PlayOneShot(clip, volume) from anywhere. One non-spatial source on the SFX bus.

UIAudio — menu SFX

Assets/_Game/Systems/Audio/UIAudio.cs. Static class with seven verbs (Move/Submit/Cancel/Tab/Success/Refuse/Tick) on the UI bus. Dispatched automatically by the menu framework — designers never wire these.

04The boss music beats

The boss corridor is a scripted audio sequence (Assets/_Game/Systems/Run/ProcGen/BossArenaSequence.cs). The introduction plays in a hush: level music fades out for the exchange, music returns at fight-on, then fades again so the boss's last words land in quiet.

  1. Door seals behind you (OnClosedBehind) → MusicDirector.StopForBossIntro(). Level music fades to silence over 0.8 s.
  2. Canned walk-in — the player strides in on the UI input map (walkInDistance default 4, walkTimeoutSeconds default 3), then a 0.4 s beat of stillness. Silence holds.
  3. Adds spawn staggered (spawnInterval default 0.45 s), dormant; the boss arrives last after its entranceDelay.
  4. Dialogue plays with the world still running — no time freeze, no music.
  5. Fight-on: boss theme erupts from silence (the default 0.3 s crossfade — PlayBossTrack passes no fade of its own) — or, if the boss has no theme, the level track restarts. Enemies wake, the gate arms, control returns.
  6. Boss falls → the gate opens: MusicDirector.FadeOutForVictory() winds the theme down to silence over 1.0 s; a ~1.2 s breath holds while it fades, then the reward spawns and the boss speaks its Victory line in the quiet. Music stays out until the next scene loads.
// BossArenaSequence.Sequence() — the fight-on branch:
if (boss != null && boss.musicTrack != null)
    MusicDirector.PlayBossTrack(boss.musicTrack);  // theme erupts out of the hush
else
    MusicDirector.ResumeSceneMusic();              // no theme = level track restarts

Any scene change afterwards hands music back to the normal scene rules — the boss theme never leaks out of the arena.

The split that bites: EnterSound lives on the shared definition — tuning one hound's telegraph tunes every hound. hurtSound lives on the prefab. The Workbench's Enemy Presentation tab edits both in one place and labels which is which.
The player-body seam, and where each kind of sound goes. Until 2026-08-17 no PlayerStateConfig carried an AudioClip field at all, so jump, land, dash, wall-slide, being hit and dying were silent by construction — there was nowhere for a designer to put a clip. Three seams now cover it. A state entry goes on PlayerStateConfig.EnterSound + EnterSoundVolume, mirroring the enemy field exactly and played by the same shape of hook (OnStateChanged, plus a named call for the initial state — SetInitialState does not raise the event, which is the trap the enemy half found first). Landing, being hurt and the death sting go on PlayerBodyAudio on Player.prefab: landing has no state of its own (falling returns to idle or run, and hanging the thud on either would fire it whenever the player stopped or started), being hurt is not a state yet, and the death sting cannot be a state EnterSound — the death state is code-registered with no config, and the enter-sound hook reads the config map, so that seam can never reach it; PlayerBodyAudio.deathSound is the seam it gets instead. The world has HealPickup.pickupSound, Secret.pickupSound and InteractZone.interactSound, the last inherited by all eight zone classes. Since 2026-08-23 the slots ship filled with placeholder clips (Assets/_Game/Audio/Placeholder/, from the committed generator — §10): Player.prefab carries player_land/player_hurt/player_death, PlayerDef's jump, dash and wall-slide states carry EnterSounds, and the pickups carry pickupSounds. InteractZone.interactSound alone stays empty on purpose — it is the designer slot. PlaceholderAudioTests.TheWiredSlotsResolveOnTheShippedAssets pins the wiring; the audio-pass state lives on Documentation/OUTSTANDING.md, the row "The player body makes no sound".
Not yet in game: RangedWeaponDefinition.DrawSound exists but is never played — no code plays it at all, and the Workbench prints exactly that. Don't spend authoring time on it. (The reason used to be given as “shots are instant casts”; that is no longer true of the bow, but this field is still unplayed.)

Four sliders + four mutes on the Settings AUDIO tab map straight onto the buses (Assets/_Game/Systems/Settings/GameSettings.cs). Every setter re-applies immediately — apply-as-you-store, no Apply button.

Percent-to-decibel is a log taper, so the slider feels linear to the ear:

// GameSettings.PercentToDb — log taper, floored at the mixer's silence:
static float PercentToDb(int percent) =>
    percent <= 0 ? -80f
                 : Mathf.Log10(Mathf.Clamp(percent, 1, 100) / 100f) * 20f;
// 100% = 0 dB · 80% ≈ -1.94 dB · 50% ≈ -6 dB · mute = -80 dB floor
The one-frame re-apply gotcha: a mixer SetFloat during BeforeSceneLoad boot gets silently reset when the mixer snapshot initializes. GameSettings.Initialize() applies the listener half immediately; the mixer half is re-applied one frame after first scene load by GameAudio's throwaway VolumeApplier. If you ever add early-boot audio code, never SetFloat mixer params before the first scene — use the same pattern.

09Add or replace a clip, end to end

Replacing a clip under its existing filename is the whole job — every wire is by filename or by asset reference, so nothing needs re-pointing. Everything below is for a new sound on new wiring.

  1. Author a mono 44.1 kHz WAV that follows the style contract in §10. §10 is the contract — and it is executable for the newer clips: Tools/AudioPipeline/synthesize_placeholder_sfx.py is committed and implements both finish chains (arcade_finish, ui_finish), so a new body, world or UI clip should be added to it and regenerated rather than hand-rolled. Only the three original combat/bow/UI generators are absent (see the honest box). Synthesize deterministically anyway: regenerating with the same filenames is what keeps every Unity wire.
  2. Drop it in the right home: Assets/_Game/Audio/SFX/ (combat), Assets/_Game/Audio/Resources/UISfx/ (UI — the filename is the wire: ui_move etc.), or Assets/_Game/Audio/Music/ (music). Replacing with the same filename ends the job — every wire holds.
  3. Import settings: stock defaults, nothing to replicate. Verified on sfx_hit_spark.wav.meta: Decompress On Load, Vorbis quality 1, normalize on, preload off, no force-to-mono. (The meta's sampleRateOverride: 44100 is inert — sampleRateSetting is "preserve" and the source WAVs are already 44.1 kHz.)
  4. New clip on new wiring: open Gleamwood ▸ Content Workbench, find the sound row for the seam (§06), drop the clip, press Play to preview in place.
  5. Sound plays through a new prefab AudioSource? Route it: set the output group to SFX by hand, use GameAudio.SfxGroup at runtime (the GPUExplosion pattern), or just run Gleamwood ▸ Audio ▸ Create + Route Game Audio Mixer — the sweep re-points every prefab AudioSource for you. Code-driven one-shots simply call GameAudio.PlayOneShot(clip, volume).
  6. Music slots: assign in Assets/_Game/Audio/Resources/MusicSet.asset (global), the biome asset (Workbench Levels tab or musicTrack = in GameContent.ini), or the boss asset (Boss Staging or the INI's [Boss:] section).

10The canon SFX style — so new sounds match

The whole combat pack is one family: Street Fighter / Final Fight arcade character, deterministic numpy synthesis (44.1 kHz mono WAV, seeded RNG — regenerating with the same filenames keeps every Unity wire). Two deliberate exceptions: the bow is natural, the UI is clean.

Combat — the CPS recipe

Layered impacts (sine thump + damped mid knock + noise slap, 16 ms flams on heavies), breathy body-heavy whooshes with hump envelopes, rising resonant charge sweeps, KO booms with falling tails. Finished through arcade_finish: lowpass 5.2 kHz → sample-rate crunch to ~11 kHz → tanh drive 1.4–2.4 → normalize 0.7–0.9. Dry and tight.

Bow — the natural exception

Real-release anatomy, no tonal sweeps: sharp string-snap click, short Karplus-Strong string ring, low wood-body thunk, faint arrow whizz. Light finish (lowpass 6.5 kHz, half-rate hold, drive 1.35) so it stays clean. Covers exactly four clips: bow_release, bow_release_perfect, arrow_shot, arrow_hit.

UI — clean blips

Fighting-game-menu flavor: crisp blips, no crunch. Lowpass 9 kHz + mild tanh 1.2. ui_move 740 Hz blip · ui_submit 660→990 two-blip rise · ui_cancel 620→415 fall · ui_tab noise swish · ui_tick 1760 Hz 30 ms micro-blip.

Enemy sounds scale by class

Each S/M/L family generates its own telegraph (riser), strike (flammed bap), death (KO boom), and hurt (lighter bap), scaled by one dict — size a new enemy's sounds by picking its class, not by inventing numbers:

ClassDuration ×f0 / f1 (Hz)Knock (Hz)
S1.0260 / 110520
M1.35190 / 80400
L1.8140 / 55300

Which enemy is in which class is not here on purpose — that roster drifts with every enemy added, so it lives in §07's wiring table beside the clips it explains. DemonKing appears in neither: it has no class sounds assigned at all.

Specials sit on top of the families: sfx_explosion_bomber (bap + rumble + 130→32 Hz sweep), sfx_death_wisp (breath sweep + high shimmer, soft finish), sfx_death_boss (double KO boom, second delayed 0.28 s, + 1.3 s rumble).

The contract for any new sound: mono 44.1 kHz WAV. Combat = layered (thump+knock+slap or whoosh+body), 5.2 kHz band-limit + ~11 kHz rate crunch + tanh drive, dry and tight, sized S/M/L by the class dict. Bow family = natural anatomy, no sweeps, light finish. UI = clean blips ≤ 9 kHz, no crunch. A sound that skips the finish chain will stick out of the mix like a stock-asset thumb.

The original generators are not in the repo — recorded for provenance, not as something you can open or run: synth_sfx_pack_v2.py (combat, seed 0x5F2A), synth_bow_natural.py (bow, seed 0xB0B0, wrote straight into Assets/_Game/Audio/SFX), synth_ui_sfx.py (the first five UI blips, seed 0x0111). Their committed successor IS in the repo: Tools/AudioPipeline/synthesize_placeholder_sfx.py (seed 0x0112) regenerates ui_success/ui_refuse and the nine placeholder body/world clips byte-identically, every .meta guid derived from the asset path so a regeneration can never re-guid a wire — see Documentation/PROVENANCE.md. The v1 chiptune pack is superseded — v2 kept all 28 combat filenames, so nothing rewired.
