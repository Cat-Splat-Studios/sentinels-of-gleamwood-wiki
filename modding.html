Modding Gleamwood

No Unity, no compiler, no account — a plain text file dropped next to the game. This page is the five-minute version; the three domain pages are the deep dives. Everything here is a player-facing feature that ships in the build.

01What you can change

Gleamwood reads a Mods/ folder that sits beside the game's executable. Anything in it is applied to a private copy each run, so your changes never touch the game's own files — delete the folder and everything is back to stock.

FolderWhat a text file there can doDeep dive
Mods/Enemies/Retune any enemy's numbers, add a new creature from an existing one, or write a whole new behaviour graph — and bring your own artwork.Enemies §10–12
Mods/Weapons/Retune any weapon (per combo swing and the dash), or add a new weapon from an existing one — its own name, stats, icon and on-hit status.Combat §10
Mods/Dialogue/Rewrite any character's lines, or translate the whole game, in the plain-text .dlg format.Dialogue §09
Mods/Player/Reskin the player — your own sprite sheet over the game's moves. A [PlayerSkin] file names the clips (with a slot for the split-body run). Changes how the player LOOKS, never what it DOES.§06 below
You never start from a blank page. Every build ships a .templates folder next to each mod folder, holding one file per shipped enemy, weapon and conversation — with the real current values, correctly spelled, every line commented out. Copy a template, delete the ; in front of one line, change the number. That is the whole workflow.

02Your first mod, in five minutes

Make the starting sword hit like a truck. Nothing to install.

  1. Find the game folder. The one with Gleamwood.exe in it. Next to it is a Mods/ folder (a build creates it empty) and a Mods/Weapons.templates/ folder full of examples.
  2. Copy a template. Copy Mods/Weapons.templates/DefaultSword.ini into Mods/Weapons/. It is all comments, so on its own it changes nothing.
  3. Uncomment one line. Open your copy and find ; BaseDamage = 1. Delete the ; and the space, and change the number: 
    ; before
; BaseDamage = 1
; after
BaseDamage = 25
  4. Run the game. Start a run and swing. The sword now deals 25.
  5. Check it loaded. Open the player log (see §04) and find the GLEAMWOOD WEAPON MOD REPORT block — it says what loaded and, if you fat-fingered something, exactly which line and why.
Made a typo? A misspelled field or a value that is not a number is written to the log and then ignored — the weapon keeps its shipped value. One bad line can never break the game, and the report names it.

03Adding something new, not just retuning

The same files can DECLARE new content, built from an existing thing so it always works. A new weapon is the same type as its donor (a bow stays a bow); a new enemy borrows a shipped creature's animations, so it can never get stuck on a move that was never drawn.

; Mods/Weapons/frostbite.ini  — a new bow that sets things alight
[NewWeapon:Frostbite]
basedOn         = DefaultBow
weight          = 1              ; how often a pedestal offers it
WeaponName      = Frostbite
BaseDamage      = 14
StatusesToApply = Ignite         ; a status, named
icon            = frostbite.png  ; optional, from Mods/Weapons/sprites/

; Mods/Enemies/glass_hound.ini  — a fast, fragile hound
[NewEnemy:GlassHound]
basedOn   = CinderHoundDef
MaxHealth = 3
tint      = #88ddff
weight    = 2

[NewEnemy:GlassHound.state:chase]
SpeedMultiplier = 1.8
A declared enemy can go further than a variant. The [Graph:] tier lets an enemy declare its own states, transitions and attack chains in text — a genuinely new behaviour, still safe because it plays from a clip set that reports an unknown animation loudly instead of freezing. Weapons have no state machine, so they stop at "new weapon". Both deep dives cover the full grammar: Enemies §11, Combat §10.

04Did it work? Read the report

Every launch, before the first room, the game writes a short block per mod folder to its log — silent only when you have no Mods/ folder at all. It is the fastest answer to "is my mod loading".

======== GLEAMWOOD WEAPON MOD REPORT ========
folder : ...\Gleamwood\Mods\Weapons
enabled: True   (build — always on)
retuned weapons : 1   [Weapon:...]
declared weapons: 1   [NewWeapon:...]
    OK  Frostbite            ranged, 14 dmg, icon, weight 1
RESULT: OK — 1 declared, 1 retuned.
=============================================

Find the log at %USERPROFILE%\AppData\LocalLow\Cat Splat Studios\Sentinels of Gleamwood\Player.log (Windows). A line that starts FAILED or a message under -- N message(s) -- tells you the file, the line and what was expected.

Only object numbers, words and switches are text-moddable. You cannot name a sound, a projectile or an animation in a text file — there is no way to point at one — so those fields are not offered in the templates at all. Artwork is the exception with its own route: enemies can bring a sprite sheet their animations are cut from (Enemies §12), and a new weapon can carry an icon.

05A worked example to copy

The repo ships a small, friendly pack you can read end to end and drop in as-is.

LocationWhat it is
Documentation/ExampleMod/A tasteful example. A couple of retunes, a glass-cannon hound and a status-bow, each heavily commented to read as a tutorial. Copy its Mods/ folder next to the game.
Documentation/TestModpack/A deliberately garish verification pack. Every tier at once, weighted to dominate, for proving the whole stack survived a change. Not fun to play — built to be obvious in a screenshot.

In the Unity project these are regenerated from menus (Gleamwood ▸ Dev ▸ Weapons ▸ Generate Mod Templates, Gleamwood ▸ Dev ▸ Enemies ▸ Generate Test Modpack) so they never drift from the code that reads them. In the editor, mod loading is behind Gleamwood ▸ Enemies / Weapons ▸ Simulate Mod Overrides so authoring is never quietly beaten by a stray folder; in a shipped build it is always on.

06Reskin the player

The player is moddable in exactly one way: its look. Drop your own sprite sheet over the game's moves. The states, the timing, the feel are the game's and stay compiled — a skin can only change which pixels play, which is the whole reason the player was moved onto the same clip system the enemies use.

; Mods/Player/emberknight.ini
[PlayerSkin]
sprite = emberknight.png 12x8    ; your sheet in Mods/Player/sprites/, cols x rows
pivot  = 2                     ; feet 2px above a cell's bottom
clips  = extend                ; keep the shipped art for clips you don't redraw

clip Idle      = 0-18  fps 25
clip Run       = 24-35 fps 18 slot Legs       ; the legs, during the split run
clip Upper_Run = 36-47 fps 18 slot UpperBody pivot 38,52  ; torso, pinned where it meets the legs
The one player-specific thing is slot. While running, the legs and torso animate on two separate renderers, so some clips carry slot Legs or slot UpperBody. Keep those exactly as the template lists them, or a frame shows on the wrong half of the body. Everything without a slot is the whole body on the main renderer. (That the grammar even has a slot is why enemies and the player share one reader — enemies simply never write it.)
Connecting the halves: pivot takes x,y. The torso must sit exactly where it meets the hips, and on a sheet whose halves are not perfectly centred that is not the middle of the frame. pivot = 2 sets the vertical only (x stays centred); pivot = 38,52 sets both — x pixels from the left, y pixels from the bottom. Measure the connection point off your art. The same two-number form works for enemy art (§12) and anywhere a sheet's centre is not its anchor.

You never start from a blank page here either: a build ships Mods/Player.templates/PlayerSkin.ini listing every clip the player has — all 26 body clips and the 9 torso clips — each with its slot and the right frame rate, every line commented out. Regenerate it any time with Gleamwood ▸ Dev ▸ Player ▸ Generate Skin Template. With clips = extend you can reskin just the idle and run and leave the rest shipped.

Refused / notedBecause
a clip name the player doesn't haveReported and ignored — a typo can't blank the character. The template lists the real names so there's no guessing.
a frame past the sheetThe whole skin is refused (not partly applied) and the player keeps its shipped art — a half-loaded skin is worse than none.
changing what the player DOESNot possible: a skin only supplies frames. Moves, timing and states are compiled. This is the deliberate ceiling — Mods/Player/ has no behaviour tier the way enemies have [Graph:].

Editor and build diverge like the rest: builds always load; the editor only under Gleamwood ▸ Player ▸ Simulate Mod Overrides. The GLEAMWOOD PLAYER SKIN REPORT block in the log says what loaded.
