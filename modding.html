Modding Gleamwood

No Unity, no compiler, no account — a plain text file dropped next to the game. This page is the five-minute version; the three domain pages are the deep dives. Everything here is a player-facing feature that ships in the build.

01What you can change

A mod is a campaign: one folder under Mods/, beside the game's executable, with a mod.ini naming it. You pick a campaign when you start a new save, and that save is bound to it — exactly one campaign is ever active, so a campaign can never reach a vanilla save or anybody else's. Everything is applied to a private copy each run, so your files never touch the game's own — delete the folder and that save reports the campaign as missing rather than quietly becoming something else.

Mods/
  my-campaign/          <-- the folder name IS the campaign id
    mod.ini            <-- without this the folder is ignored entirely
    Enemies/  Weapons/  Dialogue/  Player/  Progression/
    Campaign/          <-- the run's shape
      Rooms/           <-- and your own rooms, drawn as text
Folder inside your campaignWhat a text file there can doDeep dive
Enemies/Retune any enemy's numbers, add a new creature from an existing one, or write a whole new behaviour graph — and bring your own artwork.Enemies §10–12
Weapons/Retune any weapon (per combo swing and the dash), or add a new weapon from an existing one — its own name, stats, icon and on-hit status.Combat §10
Dialogue/Rewrite any character's lines, or translate the whole game, in the plain-text .dlg format.Dialogue §09
Player/Reskin the player — your own sprite sheet over the game's moves. A [PlayerSkin] file names the clips (with a slot for the split-body run). Changes how the player LOOKS, never what it DOES.§06 below
Progression/Set the economy. Retune what the Shopkeeper sells and what it costs, retune the per-run modifiers a run can pick up, or declare your own of either. This is what stops a campaign playing Gleamwood's progression with its own content.§08 below
Campaign/Re-web the run itself. Which biomes you visit, in what order, which branch, where it ends — plus retunes of any biome along the way. And in Campaign/Rooms/, your own rooms as .room drawings: the one place a text file makes a genuinely new asset rather than recombining shipped ones. This is what makes a campaign a campaign rather than a pile of retunes.§07 below
Where this is going: a campaign is a whole game. The destination is maker mode — Gleamwood becomes a 2D roguelite maker and ships as its own first campaign. Every seam on this page is judged against one question: if a campaign supplied all of it, would anything of ours still be load-bearing? That is why "can I change this?" keeps being answered with a text file rather than a plugin API, and why the folders above cover the run's shape, its creatures, its weapons, its voice, its look and its economy. Where the answer is still no, this page says so out loud rather than letting the maker-mode line read as delivered — see §08, where the moveset and the traversal abilities can be retuned but not extended.
You never start from a blank page. Every build ships a complete campaign you can copy: Mods/_Templates/example-campaign/, holding a mod.ini plus one file per shipped enemy, weapon and conversation — with the real current values, correctly spelled, every line commented out. Copy that folder up into Mods/, rename it, delete the ; in front of one line, change the number. That is the whole workflow. (It sits inert where it ships — the game only looks one level under Mods/ for a mod.ini, so the template never shows up as a playable campaign.)

02Your first mod, in five minutes

Make the starting sword hit like a truck. Nothing to install.

  1. Find the game folder. The one with sentinels-of-gleamwood.exe in it — that name is pinned, because Steam's launch option points at a fixed path and a versioned executable would break it on every upload. Next to it is a Mods/ folder holding _Templates/example-campaign/.
  2. Copy the example campaign. Copy Mods/_Templates/example-campaign/ up one level into Mods/ and rename it to my-campaign. Open its mod.ini and change name to whatever you want to see on the menu. Everything else is comments, so on its own it changes nothing.
  3. Uncomment one line. Open your copy and find ; BaseDamage = 1. Delete the ; and the space, and change the number: 
    ; before
; BaseDamage = 1
; after
BaseDamage = 25
  4. Run the game. Start a new save and pick your campaign — the name you set in mod.ini — when it asks which campaign to play. A slot is bound to its campaign at the moment it is created and never again, so loading an existing save will not see your file at all. Then start a run and swing. The sword now deals 25.
  5. Check it loaded. Open the player log (see §04) and find the GLEAMWOOD WEAPON MOD REPORT block — it says what loaded and, if you fat-fingered something, exactly which line and why.
Made a typo? A misspelled field or a value that is not a number is written to the log and then ignored — the weapon keeps its shipped value. One bad line can never break the game, and the report names it.

03Adding something new, not just retuning

The same files can DECLARE new content, built from an existing thing so it always works. A new weapon is the same type as its donor (a bow stays a bow); a new enemy borrows a shipped creature's animations, so it can never get stuck on a move that was never drawn.

; my-campaign/Weapons/frostbite.ini  — a new bow that sets things alight
[NewWeapon:Frostbite]
basedOn         = DefaultBow
; how often a pedestal offers it
weight          = 1
WeaponName      = Frostbite
BaseDamage      = 14
; a status, named
StatusesToApply = Ignite
; optional, from Weapons/sprites/
icon            = frostbite.png

; my-campaign/Enemies/glass_hound.ini  — a fast, fragile hound
[NewEnemy:GlassHound]
basedOn   = CinderHoundDef
MaxHealth = 3
tint      = #88ddff
weight    = 2

[NewEnemy:GlassHound.state:chase]
SpeedMultiplier = 1.8
Notes go on their own line — never after a value. In Weapons/, Enemies/, Player/ and Progression/ a ; only opens a comment at the start of a line. Written after a value it stays part of that value, which then fails to read and silently leaves the shipped number in place — the line looks perfectly reasonable and does nothing. (mod.ini and Campaign/ use a different reader that does strip a trailing ;, which is exactly how the habit gets picked up — see §07, where it is legal.) The rule is deliberate: a value may legitimately open with #, like tint = #88ddff. When a value will not read, the log now names this as the likely cause.
A declared enemy can go further than a variant. The [Graph:] tier lets an enemy declare its own states, transitions and attack chains in text — a genuinely new behaviour, still safe because it plays from a clip set that reports an unknown animation loudly instead of freezing. Weapons have no state machine, so they stop at "new weapon". Both deep dives cover the full grammar: Enemies §11, Combat §10.

04Did it work? Read the report

Every launch, before the first room, the game writes a short block per domain to its log — silent when you are playing vanilla, since there is then nothing to report. It is the fastest answer to "is my campaign loading".

======== GLEAMWOOD WEAPON MOD REPORT ========
folder : ...\Gleamwood\Mods\ashfall\Weapons
enabled: True   (build — always on)
retuned weapons : 1   [Weapon:...]
declared weapons: 1   [NewWeapon:...]
    OK  Frostbite            ranged, 14 dmg, icon, weight 1
RESULT: OK — 1 declared, 1 retuned.
=============================================

Find the log at %USERPROFILE%\AppData\LocalLow\Cat Splat Studios\sentinels-of-gleamwood\Player.log (Windows). That second folder is the product name, not the title on the window — lowercase and hyphenated, exactly as it is spelled here. A line that starts FAILED or a message under -- N message(s) -- tells you the file, the line and what was expected.

Only object numbers, words and switches are text-moddable. You cannot name a sound, a projectile or an animation in a text file — there is no way to point at one — so those fields are not offered in the templates at all. Artwork is the exception with its own route: enemies can bring a sprite sheet their animations are cut from (Enemies §12), and a new weapon can carry an icon.

The editor and a build load mods differently

This is worth knowing before you trust a test: a build always loads mods; the editor loads them whenever a campaign is active, and the Simulate Mods toggles only force a domain on when no campaign is bound. Picking a campaign is already an explicit choice, so it needs no second opt-in — and without that, the editor would silently disagree with a build, the slot naming a campaign while the game played vanilla. The build branch is the one players hit, and it is the one a test pack exists to exercise.

06Reskin the player

The player is moddable in exactly one way: its look. Drop your own sprite sheet over the game's moves. The states, the timing, the feel are the game's and stay compiled — a skin can only change which pixels play, which is the whole reason the player was moved onto the same clip system the enemies use.

; my-campaign/Player/emberknight.ini
[PlayerSkin]
; your sheet in Player/sprites/, cols x rows
sprite = emberknight.png 12x8
; feet 2px above a cell's bottom
pivot  = 2
; keep the shipped art for clips you don't redraw
clips  = extend

clip Idle      = 0-18  fps 25
; the legs, during the split run
clip Run       = 24-35 fps 18 slot Legs
; the torso: THE SAME FRAMES as the legs clip above
clip Upper_Run = 24-35 fps 18 slot UpperBody
The one player-specific thing is slot. While running, the legs and torso animate on two separate renderers, so some clips carry slot Legs or slot UpperBody. Keep those exactly as the template lists them, or a frame shows on the wrong half of the body. Everything without a slot is the whole body on the main renderer. (That the grammar even has a slot is why enemies and the player share one reader — enemies simply never write it.)
The paired clips must be given the SAME FRAMES. Three pairs exist — Run+Upper_Run, RunBowCharge+Upper_RunBowCharge, RunBowShoot+Upper_RunBowShoot. They are not two animations. They are one drawing, cut across the waist by a shader, so the legs can keep their own timing while the arms do something else — that is what lets the player run and aim at once. Point a pair at two different drawings and your character visibly comes apart at the belt: on the shipped archer, one drawing joins to within 2.7px and two drawings never got below 11px, whatever we tried. Note the example above gives both clips frames 24-35.
Pivot: one number, and both halves share it. pivot = 2 means "my character's feet sit 2px above the bottom of a frame". Because the halves are one drawing, they anchor identically — there is nothing to line up by hand, and you should not give a torso clip its own pivot. (An x,y form exists and still applies to enemy art, §12, where a sheet's centre is not its anchor. It used to be needed here too, back when the torso was separately drawn art painted over the legs; a hand-tuned anchor is exactly what the shader cut removed.)

You never start from a blank page here either: a build ships Mods/_Templates/example-campaign/Player/PlayerSkin.ini listing every clip the player has, body and torso, each with its slot and the right frame rate, every line commented out. It is regenerated from the shipped animation set on every build — so it grows when the player does, and the count in it is never something this page has to keep up with. Regenerate it by hand any time with Gleamwood ▸ Dev ▸ Player ▸ Generate Skin Template. With clips = extend you can reskin just the idle and run and leave the rest shipped.

Refused / notedBecause
a clip name the player doesn't haveReported and ignored — a typo can't blank the character. The template lists the real names so there's no guessing.
a frame past the sheetThe whole skin is refused (not partly applied) and the player keeps its shipped art — a half-loaded skin is worse than none.
changing what the player DOESNot possible: a skin only supplies frames. Moves, timing and states are compiled. This is the deliberate ceiling — Player/ has no behaviour tier the way enemies have [Graph:].

Editor and build diverge like the rest (§05). The GLEAMWOOD PLAYER SKIN REPORT block in the log says what loaded.

07Re-web the run

Everything above changes what is in the game. This changes the shape of a run: which biomes, in what order, where it branches and where it ends. Files go in Campaign/ inside your campaign folder, and the key names are the same ones the game's own content file uses — a block copied out of GameContent.ini means the same thing here.

; my-campaign/Campaign/web.ini
[Plan]
entry       = ash-start      ; where every run begins

[Node:ash-start]
biome = emberfall            ; a biome ID (not an asset name)
rest  = Rest_EmberTrail      ; the rest after it — the path doors live there
next  = ash-mid, ash-side    ; a two-way fork

[Node:ash-mid]
biome = cinderway
rest  = Rest_EmberTrail
next  = ash-end

[Node:ash-side]
biome = ashen-vaults
next  = -                    ; '-' = FINAL. Clearing it ends the run.

[Node:ash-end]
biome = pyre-crown
next  = -

; Retune a biome for THIS campaign only. The shipped one is never touched.
[Biome:emberfall]
displayName = Ashfall Reach
minRooms    = 8
boss        = Boss_Krag
The web is replaced, not merged. The moment your campaign writes one [Node:] block, it owns the whole web — the shipped one is set aside entirely. A graph cannot be half-merged without inventing an order nobody wrote, so it is all or nothing.
Trailing comments are fine here. Notice the ; where every run begins notes sitting after values above — legal in Campaign/ and in mod.ini, because these files share the reader the game's own GameContent.ini uses, and it strips a mid-line ;. That reader is the exception: in Weapons/, Enemies/, Player/ and Progression/ the same habit silently voids the value (§03). If you only remember one rule, put every note on its own line and it is always correct.

What you can name

Names resolve against the shipped game's content, plus any room this campaign drew itself (see below). You can recombine any of it; apart from rooms, you cannot invent new assets from a text file.

Choosing the shape of a level

Six keys pick between three generators. Chain is only the enum's default — every biome the game ships is Branching, and GameContent.ini reads these same keys, so a block copied out of it means here exactly what it means there.

KeyApplies toWhat it takes
topologyallChain (a spine left to right with dead-end spurs) · Lattice (a rolled grid of columns and bands, which can carry loops) · Branching (a trunk, a vertical fan column at its end, and one eastbound path leaving each storey — as many ways out of the level as branches asks for, one behind the boss and the rest slip-aways. Shipped biomes ask for 4, except Galewatch and the Hollow Deep at 2).
latticeTierLatticeArc (one loop) · Stack (a loop with a shaft standing on it) · Web (an arc off the arc — two nested loops). The generator comes DOWN this list until a shape your rooms can build fits, and names the room that would have bought the one above. Asking for more than you have costs a log line, never the level.
branchesBranchingHow many PATHS the level offers, including the boss road. Path 0 always carries the boss corridor, arena and exit; the rest end in SlipAway rooms. 1 is legal and means a forced-boss level with no way to skip the fight.
pathRoomsMin · pathRoomsMaxBranchingHow many rooms ONE path owns. The boss road spends part of that budget on its corridor and arena. Defaults are 4–6, and they are measured — swept over 200 seeds of the shipped pool, that is the largest budget that keeps every level inside 28–41 rooms and a minimap more readable than the chain it replaces. 5–8 gives 34–46 rooms and a worst case of 0.62 px/cell against the chain's 0.55: bigger levels, drawn as a smear.
bandHeightBranchingHow tall one path's lane is, in cells. Must exceed the tallest room in your pool or nothing can be placed — and the fan base is deliberately exactly one band tall, which is what makes the storey above it land on the next band's floor. The slack above your tallest room is exactly how much vertical jog a path is allowed.
An unknown value here is named, not swallowed. topology and latticeTier parse as enums; a value that is not one is reported with the list of valid ones, and the shipped setting is kept. That care exists because these keys were once the opposite: the generators were written and tested while no reader accepted a key for them, so a shape the runtime fully honoured was one no author could ask for. A knob nobody can turn is welded shut — and a generator no content can reach does not exist as far as a player is concerned.

Your own rooms

A campaign can supply its own level geometry as text: every Campaign/Rooms/*.room file is read at load and built into a real room, which you then name in a biome's roomPool like any shipped one. This is the one place the "you cannot invent new assets from a text file" rule does not hold.

A .room file is genuinely a drawing: a two-line header (room: for the name, tags: for its role) and then a grid: of characters, where the doors are drawn into the walls rather than declared. The ten in Documentation/ExampleMod (§05) are written to be read as the tutorial: lat-junction.room in particular shows why an ability gates a journey rather than a room. Every declared room goes through the same auditor the shipped prefabs do, at load — so a drawing that would strand the player (a door you can arrive through and then leave by no other) is refused with the reason, rather than wasting a run.

Enemies you declared still work here. A campaign that adds a creature in Enemies/ and retunes a biome in Campaign/ gets both: the retuned biome still rolls from the same spawn table, so your new enemy appears in it with nothing extra to wire.

When it is wrong, it refuses

A name that does not resolve, or a web that cannot be played — an entry pointing nowhere, a door to a node that does not exist, a node nothing can reach, a loop with no ending — refuses the campaign. The slot will not start, and it tells you which line is at fault. That is deliberate: dropping you into a half-broken run would waste more of your time than refusing to start does.

A value that will not parse is different: minRooms = eight is reported and the shipped number is kept, so one typo does not silently flatten a biome to zero rooms. Same for a key nobody recognises — reported, and the rest of the file still applies.

Editing a web under your own save. A suspended run remembers the shape of the web it was suspended on. Change that shape — add a node, rewire a door, point a node at a different biome — and that run is reported as unresumable rather than quietly continuing into a different game. The save survives; only the run in progress is lost, and you start a fresh one on the new web. Retuning a biome's numbers does not do this, so you can tune room counts all day with a run in flight.

One biome key is the exception, and it is the only one: topology. Every other biome number changes how BIG a level is; topology changes what a level IS — a Chain node has one way out where a Branching one has several, and layouts are regenerated from the seed rather than stored. So a run suspended under one topology and resumed under another would not strand, it would silently RELOCATE: same seed, same node, an entirely different level, and nothing said so. That is worse than a refusal, which is why topology rides the fingerprint along with the web's own shape. A [Biome:] retune reaches it because the retune is what the node is bound to.

08Set the economy

A campaign that supplies its own rooms, enemies, weapons and conversations is still selling Gleamwood's upgrades at Gleamwood's prices. Progression/ is the last thing a campaign was renting: what a profile can buy, what a run can become, and what a run earns.

; my-campaign/Progression/Progression.ini

; retune what the Shopkeeper sells
[Upgrade:vigor]
perLevel = 15
baseCost = 80

; declare one of your own
[NewUpgrade:keen-edge]
displayName = Keen Edge
description = Every weapon hits a little harder.
effect      = DamagePercent
perLevel    = 4
maxLevel    = 3
baseCost    = 120
costGrowth  = 60

; retune a MOVE the player buys — the key is MoveKey's grammar
[Move:aerial:down]
displayName = Meteor
description = Drive them into the floor.
cost        = 40

; retune an ABILITY
[Ability:dash]
cost = 350

; retune a per-run modifier
[RunModifier:combo-cancels]
maxStacks = 3

; declare one — no code, because a modifier is addressed by its EFFECT
[NewRunModifier:iron-lungs]
displayName = Iron Lungs
description = One more melee attack per airtime.
effect      = AerialAttacks
maxStacks   = 2

; declare an IMBUE — the one effect that needs more than numbers
[NewRunModifier:cruel-edge]
displayName   = Cruel Edge
description   = One of your air attacks launches this run.
effect        = Imbue
maxStacks     = 1
imbue.flag    = IsLauncher
imbue.default = aerial:forward
imbue.legal   = aerial:forward | aerial:down

; what a run EARNS — one section, no id
[Economy]
currencyName = Gleam
perKill      = 2
perDepth     = 20
clearBonus   = 100
slipBonus    = 25
perBoss      = 60

The two kinds, and why they are different

SectionWhat it isWhat effect can be
[Upgrade:]Permanent. Bought once with Gleam and kept forever, across every run on that save.MaxHp · DamagePercent · WeaponStartLevel · MeleeCancel · BowCancel
[Move:]Permanent. A directional attack the player buys once. The header is the move's MoveKey — aerial:down, ground:up, bow:up — the same string a weapon file uses to address it. Only the moves the shop sells have an entry to retune: the ones every profile owns from the start (the neutral air, and the bow's planted and running shots) are not addressable. Retune only; see the warning below.displayName · input · description · cost
[Ability:]Permanent. A movement verb. The shipped two are [Ability:dash] and [Ability:wall-jump]. Retune only, and note these also drive which rooms the generator believes are clearable.displayName · description · cost
[RunModifier:]Per-run. Picked up during a run and lost when it ends. These change rules, not numbers — "your up-air launches now" is not a number.ComboCancels · AerialAttacks · Imbue · PerfectWindow · JumpHeight · MoveSpeed · RunAccel · DashDistance · DashCooldown

An upgrade takes perLevel (how much one level grants), maxLevel, baseCost and costGrowth (added per level after the first). A modifier takes maxStacks — plus scalePerStack for the ones that multiply a value rather than count something: PerfectWindow and the five movement effects. Leave that at 1 on a multiplying effect and the entry is refused, because one stack of it would change nothing.

An Imbue takes three keys of its own

Imbue is the one effect that is not a number: it turns a single named flag on, for a single move, for one run. Those do not fit a scalar field, so they are written as dotted sub-keys — and until they existed, Imbue was an effect this page listed and a campaign could not actually declare. An entry naming effect = Imbue and nothing else names no move, and is refused.

KeyWhat it is
imbue.flagWhich flag to turn on. IsLauncher or CanBeCancelled — those two and no others, because those are the two the game can set. The name is the config field name, spelled exactly as a weapon .ini spells it. A typo is refused rather than ignored: it would otherwise be a modifier that saves, restores, shows in the panel and does nothing.
imbue.defaultThe move it points at when nothing has rolled one — and what a save written before the modifier was targeted resolves to. A move key: aerial:up, ground:forward. It must satisfy the mask below.
imbue.legalEvery move the run is allowed to roll it onto. A list separated by | or ,, where each item is either a move key (aerial:down) or a MoveSet name including the composite Melee — mix them freely. A raw number is refused: it means whatever the bits meant on the day it was typed, and that set has grown before. There is no subtraction; the melee set is seven items, so list what you want.
Only melee moves can be imbued, and leave out anything that already does the thing. An imbue writes into a MeleeAttackConfig, so a bow target could never fire — a mask that reaches outside the melee set is refused by name. The second half is your design rather than a rail: ground:up always launches, so imbuing IsLauncher onto it is a reward the player cannot see. That is why the game's own launcher lists five moves and not seven.
maxStacks is a safety cap, not a balance knob. Several modifiers raise a budget that is the only thing bounding a loop — the combo cancel is the clearest, because a large enough budget is an attack state the player never leaves. Raise them a little at a time and play the result. There is a hard ceiling of 10, and it is a refusal rather than a clamp: an entry asking for more is dropped by name, whole, and the modifier stops existing. The highest any shipped modifier declares is 3 (the combo cancel; the other nine are 1 or 2), so the ceiling leaves room to more than triple the most generous one and still catches the order-of-magnitude typo, which is the actual hazard.

What a run EARNS

Setting every price and no income only rebalances half the loop — halve what the Shopkeeper charges without touching these and the game is simply twice as generous. [Economy] is the other half. It takes no id: there is exactly one economy per campaign, so it is a section rather than a family, and it clones the shipped one the same way everything else here does.

KeyWhat it isShipped
currencyNameWhat the meta currency is called, everywhere the player sees it. Rename it and the whole game re-themes.Gleam
perKillPer enemy felled inside a biome — the moment-to-moment trickle.2
perDepthRun-end bonus per depth tier reached — what rewards pushing deeper.20

This tier buys RETUNE, not EXTEND — and the difference is worth knowing before you plan around it. You can rename, reprice, redescribe and re-cap every entry the game ships, and you can declare your own [NewUpgrade:] and [NewRunModifier:] — carrying an effect the game already has. You cannot add a move, an ability, or a new kind of effect. [NewMove:] and [NewAbility:] are refused by name rather than ignored, and the log says why: the vocabularies (MoveSet, PlayerAbilities, RunEffect, MetaEffect, AttackDirection) are compiled C# enums read at fixed seams, so a new entry would have no bit to grant and nothing would consult it — it would show up in the shop, be bought, and do nothing at all. Refusing loudly beats selling that. [Move:] and [Ability:] reach only the entries the game already ships, for the same reason — but a header naming anything else is not silent: it is reported by name, with the count of settings it changed (none), the list of real ids, and a "did you mean". That report covers all four families, so a misspelled [Upgrade:vigour] is caught the same way. It exists because this tier is otherwise strict — an unknown key inside a section was always named, so a modder who has learned the loader catches their typos had been taught to trust a clean console.

Extend is deferred, not abandoned. The eventual answer is string-keyed registries, and the reason it has not happened yet is a real cost rather than a missing afternoon: MoveSet is an allocation-free bitset tested on the per-swing path, and a registry lookup there is a per-hit cost paid by every player so that a few campaigns can add a move. That trade gets made deliberately, on the way to maker mode — the destination where Gleamwood is a 2D roguelite maker that ships as its own first campaign — not by accident. Until it is made: deferred, and this page will keep saying so.
The name in the header is a save key. vigor, combo-cancels — those strings are written into save files. You cannot set id from a file (the game says so if you try), and renaming a section in a campaign somebody has already played silently drops that upgrade from every save holding it. A [NewUpgrade:] or [NewRunModifier:] that repeats a shipped name is refused for the same reason.

When it is wrong

Refusal is per entry, never per file. A misspelled field, a value that is not a number, or an entry that could never do anything — an upgrade granting 0 per level, an Imbue modifier naming no move — is reported in the report (§04) and dropped, and the rest of the file still applies. A modded entry goes through the same validation a designer's does, so a mod cannot ship a reward that silently does nothing.

A retune can never break a move you already bought. [Move:] and [Ability:] are the two entries with teeth outside the shop — a move is a save key a weapon file also addresses, and an ability is a flag the room generator reads when it decides which levels are clearable. So if a retune leaves one unusable — a display name blanked, an input line deleted — the campaign's version is dropped and the shipped move or ability is used instead: a campaign may not break a move the player has already bought. Everywhere else a bad entry is simply dropped; here there is a purchase behind it.
