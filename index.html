01Three rules make everything editable

Every system in Gleamwood follows the same contract, which is why a designer can reach any knob — and why this wiki can promise to cover all of them:

Data first

Behavior lives on ScriptableObject definitions — weapons, enemies, bosses, biomes, statuses, player settings. Code reads data; shared definitions are never mutated at runtime (upgrades ride per-run instances).

Declare, don't wire

Attributes grow the tools: [WorkbenchCategory] adds a workbench tab, [Tunable] adds an F1 slider, [AnimatorStateRef] turns a string into a validated dropdown. Nobody maintains glue.

Validated, loudly

Two validators + the full PlayMode suite gate every change. Unreachable rooms and unregistered weapons are build-breaking errors; missing animation states flag red in the Workbench and every [AnimatorStateRef] dropdown. The exact test count lives in Logs/playmode_test_results.txt and is deliberately never copied into prose.

02The content pipeline at a glance

One flow, whatever you're making. Text config feeds assets, assets feed tools, validators guard the door.

Know which of the three tuning surfaces you're on: the Workbench edits authored assets (the source of truth), scene tuners edit those same assets visually, and the F1 panel edits the runtime copy in play mode — transcribe keepers back into the asset.
